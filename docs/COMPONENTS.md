# Components

> Generated by `npm run docs` from the header of each file in `src/components/`. Do not edit by hand — edit the component.
> Live specimens: `/kit/` (and `/th/kit/`, `/ja/kit/`). How to compose them: `docs/STORY-RECIPES.md`. Rules: `docs/DESIGN-RULES.md`.

**Localized text** (`L`): a plain string, or `{ en, th?, ja? }`. Missing languages fall back to English.
**Media keys**: `"<work-id>/<file>"` → `src/assets/works/<work-id>/<file>`. A missing file fails the build.
**Context color**: components inside an element with `data-cat="<kind>"` take that kind's colors; everything else is identity blue.

## Shell

Page frame: header, nav, section wrappers, marker, fog, footer. Most are placed once by PageShell.

### Atmosphere

`src/components/shell/Atmosphere.astro`

The misty ground behind every page: soft gradient + two tiled cloud layers + a tint whose color follows the kind of work in view.

- **Use:** Once per page. PageShell already includes it — you normally never place it yourself.
- **Avoid:** Adding grain, blobs or extra glow layers (default-deny list). Never put content inside it.
- **Behavior:** The tint is identity wash by default. It changes where a composition opts in with `data-fog`, on a page whose PageShell has `fog`, or when a list dispatches `atmo:cat` on document (detail: a category, or null for the page's own — SelectedWork does this for the project in the middle of the screen). A 700ms crossfade changes the tint. On mouse devices, the whole atmosphere drifts at 0.025 × scroll distance as one opaque canvas (after a page change it glides to the new position instead of jumping), and the canvas always reaches the bottom of the screen — even mid-fade, or back on a long page; touch and reduced motion keep it still. Static CSS layers remain visible until the canvas is ready.

```astro
<section data-cat="game" data-fog>…</section>   (opt-in: only where the work's color should reach the background)
```

### SiteNav

`src/components/shell/SiteNav.astro`

Thin sticky header: name mark (the first name, which turns into the owner's handwriting when pointed at), main nav with a sliding cursor, language switch, theme toggle.

- **Use:** Once per page (PageShell renders it). PageShell passes `nav` through as `current`.
- **Avoid:** Adding more than ~5 nav items, or icons — on phones the menu is a text button (MENU), never an icon-only hamburger.
- **Behavior:** The name mark, pointed at or focused, is written over by the owner's handwriting in the identity blue: one soft edge travels left → right, the typed name giving way behind it (Thai pages: the Thai signature; reduced motion: an instant swap; touch: stays typed). Cursor slides to the hovered item (240ms) and back; a clicked item becomes current at once. Desktop links have a wider click target from 960px. Phones (≤760px): one thin row — name + a MENU button; the button drops a panel under the header (the nav as 48px rows, language and theme below it; items come in one after another), closed by the button, Esc, a tap outside or choosing a page; the page does not scroll while it is open and focus stays inside. On pages that contain the nav's #anchors, it follows the section in view (scroll-spy). Stays still during page transitions.

| prop | type | notes |
|---|---|---|
| `current` | `string` | Key of the active nav item: 'work' \| 'about' \| 'timeline' (see NAV in src/lib/site.ts). Home has none: the name mark is its link. |

```astro
<SiteNav current="work" />
```

### ThemeToggle

`src/components/shell/ThemeToggle.astro`

Cycles Auto → Light → Dark. Auto follows the device. Remembered per browser.

- **Use:** Inside SiteNav (already there).
- **Avoid:** Sun/moon icons without text.
- **Behavior:** Switching: a plane in the new mode's ground slides in from the right (the toggle's side) on the click, covers the page, the theme switches underneath, and the plane slides on out to the left (~0.8s, soft 10° edges, transform only — no page capture; scripts/theme.ts). Nothing inside the page animates while it switches. A step that does not change what shows (Auto → Light on a light device) just changes the setting. Reduced motion: instant.

```astro

```

### WorkReel

`src/components/blocks/WorkReel.astro`

The Work page's showcase: the works side by side on one long track. On a desktop the track holds under the header and scrolling down carries it sideways (sen's sideways travel); elsewhere the works stack. A counter `[03] – [08]`, a progress line and ← → keep the place.

- **Use:** Once, on /work/. Each child is one work's panel (src/components/showcase/, built on ReelPanel), marked `data-panel` with `data-work` and `data-cat`; the reel only moves them and says which one is current (`.is-cur`). Pinned, it gives panels `--rp-vh`: the height a visual may use.
- **Avoid:** A second reel on a page; panels that are the same layout with the title and picture swapped; hiding a work's only proof in the reel (its page or links show it openly); anything that moves inside a panel with the scroll (the track is the one moving layer).
- **Behavior:** A click anywhere on a panel that has a page (its link marked `data-panel-go`) opens it, except on links, buttons, players and selected text. Pinned (hover + fine pointer, ≥1024px wide, no reduced motion): the section is as tall as the track is long, and the scroll moves the track by transform only. The panel that has reached the left edge of the column is current: `.is-cur` goes on it, the counter follows and the fog takes its color. ← → and keyboard focus inside a panel scroll the page to that panel. The view clips sideways instead of scrolling (so focus can never shift the track) and stays open above and below (a big number over a tall title is never cut). Otherwise (touch, narrow, reduced motion): the panels stack with no pin, the current one is the one across the middle of the screen, and the counter and buttons hide.

|---|---|---|
| `label` | `L` | Accessible name of the region. |

  <article data-panel data-work="vaja" data-cat="game">…</article>
  <article data-panel data-work="z80" data-cat="dev">…</article>
</WorkReel>
